# 2026-08-27 Qwen3.8-27B — `--no-async-scheduling` (MTP profiles)

`compose.yaml` now passes `--no-async-scheduling` for every spec-decode profile
(tracks `VLLM_SPEC_DECODE`). Background: on v0.28.0 async scheduling resolves to
**ON by default** when the spec method is MTP (`vllm/config/vllm.py`; MTP is in
`EagleModelTypes`), which was previously mislabeled "async is auto-disabled on
MTP". The async+MTP+hybrid-GDN+`mamba-cache-mode align` combination has an open
accepted-count race (vllm-project/vllm#51571, silent token corruption) and
vLLM's own ROCm CI disables async for MTP pending an unroot-caused hang
(#54039 / #32275). This run validates the flag change.

Stack: vLLM v0.28.0, torch 2.13, AITER v0.1.20, `ROCM_AITER_UNIFIED_ATTN`,
MTP3, TP=2, 256K max-model-len, `--gpu-memory-utilization 0.92`,
`--max-num-seqs 2`, **fp8 KV** (the live `qwen3.8-27b` profile:
`VLLM_KV_CACHE_DTYPE=fp8`; config dump confirmed `kv_cache_dtype: fp8` and
`async_scheduling: False`). Method: `llama-benchy 0.4.0`, `--pp 2048 --tg 32
128 --runs 3`, thinking off, single request. Coherence **PASSED** on every run.

## Concurrency-2 coherence smoke (exercises the #51571 condense window)

With `--max-num-seqs 2`: start request A (story, 400 tok), inject request B
(count, 120 tok) 0.7 s later so B finishes first and its removal triggers
`InputBatch.condense()` while A is mid-generation — the exact mutation window
#51571 describes. Thinking disabled (`chat_template_kwargs
enable_thinking: false`) so the full budget goes to content. Two trials:

| trial | A | B |
|:------|:--|:--|
| 0 | 400 tok / 1667 chars, coherent, finish=length | 120 tok, numbers **1→43 in strict order**, no skips/repeats, finish=length |
| 1 | 400 tok / 1729 chars, coherent, finish=length | 120 tok, numbers **1→43 in strict order**, no skips/repeats, finish=length |

Both requests hit `finish_reason: length` (budget-limited, not truncated). The
ascending-count probe is the sharpest test for the #51571 failure mode
(repeated/dropped/garbled tokens) — clean on both trials. Server logs during
the runs: only benign warmup JIT-compile warnings and pre-existing
transformers cosmetics; no errors.
