# 2026-08-25 gfx1201 unified-attention config tuning (R9700)

Per-arch tuning of aiter's `ROCM_AITER_UNIFIED_ATTN` launch config for RDNA4
(`gfx1201`, 2x R9700), driven by a new in-container sweep
(`tools/tune_ua_config.py`) that monkey-patches `select_2d_config` /
`select_3d_config` and times `unified_attention()` at the Qwen3.8-27B
full-attention geometry (GQA 24:4, head 256, KV page 832, bf16 KV). Every
candidate's output was **bitwise-identical** to the stock config (max abs
diff 0.0000) — these are pure launch-knob changes, no numerical drift.

## Sweep: 3D long-context decode (the kernel behind tg32/tg128 at depth)

Context `kv_len` in the table is total context; one generated token (bs=1).
The stock 3D config on gfx1201 is `attn_warps=2, attn_stages=1 (bf16-patch),
waves_per_eu=2` — note `waves_per_eu` is never updated in the non-gfx1250
branch of `select_3d_config`, so it stays at its default 2.

| kv_len | baseline ms | `w4:s1` ms | speedup |
|-------:|------------:|-----------:|--------:|
| 1024   | 0.095       | 0.067      | 1.42x   |
| 16384  | 0.245       | 0.130      | 1.88x   |
| 65536  | 0.659       | 0.490      | 1.34x   |
| 131072 | 1.299       | 0.924      | 1.41x   |

The win is **`attn_warps` 2 -> 4**. Refinement at d64k/d128k: every 4-warp
config lands at ~0.49ms / ~0.92ms regardless of `waves_per_eu` in {2,4,6};
`waves_per_eu=8` is marginally worse. So the change keeps `waves_per_eu` at
its default and only raises `attn_warps` to 4 for gfx1201.

**MTP-style batch decode (q_len=4)** also favors 4 warps, so the change holds
for the actual speculative-decode path, not just bs=1:

| kv_len | `w2:s1` ms | `w4:s1` ms | note |
|-------:|-----------:|-----------:|:-----|
| 65536  | 0.765      | 0.543      | w4 ~1.4x faster than w2 |
| 131072 | 1.459      | 0.993      | w4 ~1.5x faster than w2 |

## Sweep: 2D prefill (the kernel behind pp2048 / chunked prefill)

`max_seqlen_q >= 256` large-prefill config. Stock on gfx1201: `num_warps=4,
num_stages=1, TILE_SIZE=32 (upstream gfx1201), BLOCK_M=64`.

| scenario      | baseline ms | `w8:s1` ms | speedup |
|:--------------|------------:|-----------:|--------:|
| p2k (q=2048)  | 1.221       | 1.139      | 1.07x   |
| p2k ctx=64k   | 73.203      | 68.429     | 1.07x   |

Consistent ~7% win from `num_warps` 4 -> 8 on the large-prefill branch.

## 2D decode (ctx <= 512)

`w4:s1` (the stock RDNA config) is already the best of {w2,w4,w8} x {s1,s2};
no change.

## Patches

All in `patches/aiter/` (applied at build time, version-locked to AITER_REF
v0.1.20):

- `unified-attention-gfx1201-tune.patch` — the two gfx1201 branches above
  (`attn_warps=4` in 3D decode; `num_warps=8` in 2D large prefill), each gated
  on `arch.name == "gfx1201"` / `DEVICE_ARCH == "gfx1201"`, mirroring the
  existing `gfx1151` per-arch precedent.
- `unified-attention-bf16-kv.patch` (hardened this session) — RDNA bf16-KV
  LDS caps (2D decode + 3D), now gated on `arch.is_rdna`, with refs to
  ROCm/aiter#4329 / vllm#48723.
- `allowed-archs-gfx1201.patch` (new) — accept gfx1201 (and the rest of RDNA)
  in the build-time `csrc/cpp_itfs/utils.py` `allowed_archs` so a
  `GPU_ARCHS=gfx1201` prebuild path doesn't hard-assert (matches the runtime
  JIT list in `aiter/jit/core.py`).

## Tools

- `tools/tune_ua_config.py` — the sweep; run with `just down` first, then
  `compose run ... --entrypoint python <path> --scenarios ...`. Reuse it to
  re-validate the LDS guard (`triton` raises OutOfResources if a config
  exceeds the 64 KiB workgroup LDS limit — the #4329 regression check) or to
  retune after an AITER_REF bump.

## End-to-end verification

`just bench` (pp2048, tg32+128, runs 3) on the same boot, before vs after the
rebuild (same v0.28.0 code line; only the aiter patches changed):

| test   | before (tuned-off) | after (gfx1201-tuned) |
|:-------|-------------------:|----------------------:|
| pp2048 | 3026.95 ± 12.62    | 3017.73 ± 117.46 / 2881.47 ± 194.06 |
| tg32   | 74.88 ± 3.73       | 64.17 ± 4.77 |
| tg128  | 64.82 ± 6.69       | 66.12 ± 2.48 |

Coherence **PASSED** on every run (incl. a 512-token check during bench
warmup). Interpretation:

- **pp2048 (2D prefill) is unchanged** within noise. The ~7% attention-prefill
  win is diluted: pp2048 is dominated by the 48 GDN/linear layers + the 16
  full-attention layers' prefill, and boot-to-boot pp2048 already swings
  ~1.4-3.1k (08-25 doc). No regression.
- **tg32/tg128 at depth 0 (2D decode)** are unchanged within the documented
  ~±10% swing — they exercise the 2D-decode path, which the tuning leaves
  untouched (`w4:s1` was already optimal there).
- **decode at depth (3D kernel)**: a `--depth 65536 --tg 32 --no-cache` run
  reads **56.07 t/s** vs **61.93** on the 08-23 baseline (old `attn_warps=2`
  build). This is **not** a regression: tg32-at-depth has historically swung
  51-62 t/s (08-22: 51.50, 08-23: 61.93), and the q4 sweep above confirms
  `attn_warps=4` is strictly better than the old `attn_warps=2` for the exact
  MTP batch-decode shape. The end-to-end decode is dominated by the 48 GDN
  layers + MTP + TP all-reduce over PCIe, so the standalone attention-kernel
  win (1.4-1.9x, bitwise-identical) is not directly visible at the tg32-at-
  depth level. Treat the end-to-end decode-at-depth as within-noise; the
  kernel-level win is the authoritative, reproducible result.
