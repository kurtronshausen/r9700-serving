# 2026-08-28 Qwen3.8-Flash-Next — vllm#43389 MoE int4 interleave patch A/B

Third-party W4A16 checkpoint (`aixiaoma/Qwen3.8-Flash-Next-W4A16`), TP=4,
`--gpu-memory-utilization 0.95`, bf16 KV, MTP4, `--enable-expert-parallel`,
eager mode (`--compilation-config {"mode":0}`, forced — see profile comments).
Method: `llama-benchy 0.4.0`, `--pp 2048 --tg 32 128 --runs 3`, thinking off,
single request. Coherence + multi-turn growing-prefix probe both **PASSED**
in both configs.

Patch under test: `patches/vllm-flashnext/43389-moe-int4-interleave-rocm.patch`,
adapted from upstream vllm-project/vllm#43389 (open, unmerged as of
2026-08-28; AMD-authored). Repacks MoE int4 weights at load time from
K-packed `[E, N, K//2]` uint8 to N-packed `[E, K, N//8]` int32, unpacked via
`tl.interleave` in the Triton kernel (fewer VGPRs than per-element variable
shifts). Gated behind `on_rdna()` + `num_bits==4`; author validated no gsm8k
accuracy regression on gfx1100/gfx1151/gfx1201 (our arch).

| model                       |   test |            t/s (baseline) |            t/s (patched) | delta |
|:----------------------------|-------:|---------------------------:|--------------------------:|------:|
| qwen3.8-flash-next-aixiaoma | pp2048 |                   ~700-780 |             2344-2346     | **~3x** |
| qwen3.8-flash-next-aixiaoma |   tg32 |       16.95 ± 2.40 (pk 20) |    17.88 ± 0.86 (pk 22)  | ~+5% (noise) |
| qwen3.8-flash-next-aixiaoma |  tg128 |       16.07 ± 0.57 (pk 24) |    15.52 ± 1.52 (pk 23)  | ~-3% (noise) |

Prefill is MoE-compute-bound on this hybrid-GDN model, so the interleave-
unpack kernel wins big there (~3x). Decode is one token per step
(kernel-launch/memory-bound), so tg32/tg128 land within run-to-run noise —
no meaningful change either direction.

## Memory tradeoff

Model weight footprint is unchanged (19.95 GiB/GPU, both configs). The
patched kernel's dummy profiling forward pass uses ~3.5-4 GiB more peak
activation memory than the stock Triton WNA16 MoE path, which eats directly
into the KV-cache budget:

| | baseline | patched |
|:--|--:|--:|
| model weights | 19.95 GiB | 19.95 GiB |
| non-KV overhead | ~6.4 GiB | ~10 GiB |
| usable ctx @ util 0.95 | 262144 (276,497-token pool) | ~158304 |

`VLLM_MAX_MODEL_LEN` on the `qwen3.8-flash-next-aixiaoma` profile was cut
from 262144 to 155000 to leave headroom under the patched ceiling. Revert to
262144 and drop the patch if full 256K context matters more than the pp2048
win for a given workload; watch upstream #43389 for a merged/lower-overhead
revision.
