# 2026-08-10 Qwen3.6-35B-A3B MTP4 — depth sweep

Current stack (AITER unified attention, bf16 KV, MTP4,
`--max-num-batched-tokens 4096`, `--max-num-seqs 4`, tuned fused_moe configs,
froggeric v21.3 chat template). Replaces the old MTP3 depth sweep
(`08_01_a3b_moe_mtp3_depth.md`).

`ctx_*` rows = full context load (depth prefix + 2048-token prompt); `pp2048` /
`tg32 @ dXXX` = incremental 2048-token prefill / decode with the depth prefix
cached (prefix caching enabled).

> The old MTP3 sweep (`08_01_a3b_moe_mtp3_depth.md`) had no `ctx_*` split: its
> `pp2048 @ dXXX` column measured full-context prefill (depth + 2048, uncached),
> i.e. comparable to `ctx_pp` here, not to `pp2048`.

Observations:
- **Decode stays flat** ~150-196 t/s across all depths (noisy first-run d0 and
  tail-of-run d64000 excluded).
- **Prefill drops with depth**: incremental 2048-token prefill falls from ~7000
  t/s at d1024 to ~1900 t/s at d64000 as the attention span over cached prefix
  grows. Same shape as the old MTP3 sweep, lower absolute prefill at depth.
- **Full-context load (`ctx_pp`)** peaks ~11.2-11.5k t/s at d4096-d8192 and
  degrades to ~6.9k at d64000; e2e TTFT scales linearly with context length
  (258 ms @ d1024 → 9308 ms @ d64000).
- First `pp2048 @ d0` run (8386 ± 3406) is a cold outlier, consistent with prior
  benchy invocations (see `08_10_qwen3.6-35b-a3b_mtp4_envswitch.md`).
